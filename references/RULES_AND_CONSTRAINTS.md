## 1. บทนำและวัตถุประสงค์

ในการทำ Mod แปลภาษาไทยสำหรับเครื่องเกมยุคเรโทร (เช่น PS1, SFC, GBA) สถาปัตยกรรมของเกมถูกออกแบบมาบนทรัพยากรหน่วยความจำที่จำกัดมาก ไม่มีระบบ Font Rendering อัตโนมัติเหมือนคอมพิวเตอร์ยุคใหม่ การแก้ไขข้อมูลไบนารีเพียงไม่กี่ไบต์ผิดตำแหน่ง อาจนำไปสู่หายนะ เช่น:
* **หน้าจอแตก กระจายโพลิกอนเละทั่วจอ (GPU Instruction Cascade)**
* **กราฟิกฉากหลังกลายเป็นขยะสีมั่ว (VRAM Buffer Overwrite)**
* **เกมค้างตอนกดปุ่มสนทนา (Script Instruction Jam)**
* **Emulator เปิดไม่ติด หรือแผ่นเกมเสีย (Sector Size Mismatch)**

เอกสารนี้รวบรวม **"กฎเหล็กและข้อจำกัดทางเทคนิคที่ห้ามละเมิดเด็ดขาด"** ที่ค้นพบจากการทำ Reverse Engineering เชิงลึก เพื่อเป็นคู่มือคุ้มกันและส่งต่องานพัฒนาได้อย่างปลอดภัย 100%

## 2. กฎเหล็กข้อที่ 1: ระบบฟอนต์และ VRAM Buffer

### 2.1 กฎล็อกขนาดไฟล์ `MSG_CG.BIN` ต้องเท่ากับ 74,880 ไบต์เสมอ
> [!CAUTION]
> **ห้ามสร้างไฟล์ `MSG_CG.BIN` ให้มีขนาดเกิน 74,880 ไบต์ แม้แต่ไบต์เดียว!**

* **สาเหตุเชิงลึกในสถาปัตยกรรม RAM ของ PS1**:
  * ตัวเกมโหลดไฟล์ `MSG_CG.BIN` ขึ้นไปไว้ที่หน่วยความจำ **PS1 RAM แอดเดรส `0x80110000`**
  * ที่ RAM แอดเดรส **`0x80122500`** (ซึ่งตรงกับ `0x80110000 + 74,880 ไบต์พอดี`) คือจุดเริ่มต้นของ **VRAM Tile & Map Buffer** ของฉากห้องนอนและฉากแผนที่
  * หากไฟล์ฟอนต์มีขนาดใหญ่กว่า 74,880 ไบต์ ข้อมูลส่วนเกินจะทะลักไปเขียนทับหัวตาราง VRAM กราฟิกของฉาก ทำให้ฉากหลังในเกมกลายเป็นขยะสีรุ้งแตกกระจายทันที
* **ข้อกำหนดในการสร้างฟอนต์**:
  * ล็อกโควตาจำนวนตัวอักษรไว้ที่ **418 Glyphs** (รวม Token 0 Space รวมเป็น 419 รายการ)
  * ขนาดรวมส่วนฟอนต์ภาษาไทยคือ 53,504 ไบต์ และจบไฟล์ที่ Offset `0x12480` (74,880 ไบต์พอดี)

### 2.2 การล็อกระดับเส้นฐานตัวอักษร (Locked Baseline `oy = 1`)
* เพื่อป้องกันปัญหาสระและพยัญชนะไทยลอยขึ้นลงไม่เท่ากัน ในสคริปต์ `generate_thai_font_4bpp.py` ต้องกำหนด Base Baseline Offset ให้คงที่ที่ `oy = 1` เสมอ ห้ามปรับเลื่อนตามขนาดของแต่ละ Glyph โดยพลการ

### 2.3 ระบบยกระดับวรรณยุกต์สองชั้น (Mark-to-Mark Elevation Layer)
* วรรณยุกต์ (`่`, `้`, `๊`, `๋`, `์`) เมื่อต้องวางซ้อนบนสระบน (`ิ`, `ี`, `ึ`, `ื`, `ั`) จะต้องถูกยกขึ้นไปอยู่ในเลเยอร์ความสูงพิเศษด้านบน (Y: 0..3) เพื่อป้องกันไม่ให้พิกเซลของวรรณยุกต์ทับเส้นของสระบนจนขาดแหว่ง

### 2.4 การรวมพยางค์ล่วงหน้า (Precomposed Clusters)
* ในระบบ Monospace ของ PS1 หากพิมพ์สระ/วรรณยุกต์เป็นตัวเดี่ยวๆ จะกินช่องไฟและลอยเคว้ง
* คำศัพท์ที่พบบ่อยที่มีสระบน+วรรณยุกต์ หรือสระล่าง เช่น `ผู้`, `กู้`, `นี้`, `เพื่`, `ล้`, `ที่`, `นี่`, `ฟื้`, `ปู่` ต้องถูกรวมเป็น 1 Glyph สำเร็จรูป (Precomposed Cluster) เสมอ

### 2.5 การแมปเครื่องหมาย `:` (Colon) บน Token 207 (`0x00CF`)
* ในเอนจินของเกม Wataru รหัส `0x00CF` ถูก Hardcode ไว้เป็นตัวแบ่งชื่อผู้พูด (Speaker Separator)
* หาก Token 207 ไม่ได้ถูกวาดเป็น `:` ในตารางฟอนต์ ชื่อตัวละครจะแสดงผลผิดเพี้ยน (เช่น `โอบาบะ ฅ`)
* **กฎเหล็ก**: ใน `thai_table.json` รหัส `207` ต้องแมปกับตัวอักษร `:` เสมอ

### 2.6 ระบบรวบสระคู่พยัญชนะ (Dual-Syllable Compound Tiles)
* **ปัญหา**: เอนจิน Monospace ของ PS1 จะเลื่อนตำแหน่ง X ไปข้างหน้า 16 พิกเซลเสมอ (`x += 16`) หากแยกสระหน้า (`เ`, `แ`, `โ`, `ใ`, `ไ`) หรือสระหลัง (`า`, `ะ`, `ำ`) เป็นช่องเดี่ยว จะเกิดช่องว่างโบ๋ 10-12 พิกเซล ดูเป็น "สระห่างกันเป็นฟันปลา"
* **กฎเหล็ก**: ต้องรวมคู่พยางค์ความถี่สูงเข้าด้วยกันเป็น 1 ช่อง 16x16:
  - สระหน้า + พยัญชนะ (เช่น `ไป`, `ใน`, `แต`, `ได`, `ให`, `เล`, `เอ`, `เด`, `เร`, `เห`)
  - พยัญชนะ + สระ า (เช่น `มา`, `ขา`, `พา`, `วา`, `ตา`, `รา`, `กา`, `นา`, `หา`, `อา`, `สา`)
  - พยัญชนะ + สระ ะ (เช่น `นะ`, `จะ`, `คะ`, `ระ`, `ละ`, `อะ`, `ตะ`)
  - พยัญชนะ + สระ ำ (เช่น `นำ`, `ทำ`, `คำ`)
  - คำผสม 3 ตัวอักษรพิเศษ (เช่น `เมื่`, `เยื`, `เรื่`, `เพื่`, `ได้`, `ไม่`, `แต่`, `ให้`, `แล้`, `เจ้`)

### 2.7 กฎ Universal Mark-Guard ป้องกันวรรณยุกต์หลุดลอยเดี่ยว (Zero Detached Marks)
* **ปัญหา Consonant Stealing**: หากจับคู่ `เจ` แต่ในประโยคเป็นคำว่า `เจ้า` (`เ-จ-้-า`) ตัวพยัญชนะ `จ` จะถูกขโมยไปรวมกับ `เ` ทำให้ไม้โท `้` กลายเป็นตัวโดดเดี่ยว ลอยเคว้งกลางอากาศพร้อมกินช่องไฟ 16 พิกเซล
* **กฎเหล็ก**: ในฟังก์ชัน `tokenize_thai_units()` หากตัวอักษรถัดไปเป็นสระบน/ล่างหรือวรรณยุกต์ (`MARKS = set('่้๊๋์ิีึืั็ุู')`) **ห้ามตัดรวบคู่คำ 2 ตัวอักษรโดยเด็ดขาด** (เว้นแต่คู่คำนั้นจะมีวรรณยุกต์ในตัวอยู่แล้ว เช่น `เจ้`, `ได้`)

### 2.8 กฎประกันชุดอักษรพื้นฐานและ Fallback Decomposition ป้องกันเกม Crash
* **โควตา 418 ช่อง**:
  - ต้องสำรอง 91 ช่องแรกให้กับ เครื่องหมายวรรคตอน ตัวเลข (22 ตัว), สระ/วรรณยุกต์เดี่ยว (23 ตัว), และพยัญชนะไทยครบ 44+2 ตัว (`ก .. ฮ`) เสมอ
  - หากพบคำประสมหรือคลัสเตอร์หายากที่อยู่นอกเหนือจากที่บรรจุไว้ในตารางฟอนต์ ฟังก์ชัน Encode ต้องกระจายคำ (Decompose) ออกเป็นตัวอักษรพื้นฐานแทนการโยนข้อผิดพลาด เพื่อให้เกมทำงานต่อเนื่องได้ 100% ไร้อาการค้างหรือตัวหนังสือขยะ

### 3.1 กรณีศึกษา: อาการหน้าจอแตกใน `media_1789023193599.png` และสาเหตุที่แท้จริง
* **อาการที่พบ**:
  เมื่อผู้เล่นคุยบทสนทนาในฉากเปิดเรื่องไปเรื่อยๆ จนถึงช่วงซาคุยะพูด (`ซาคุยะ : ก็ท่านยายน่ะ...`) จู่ๆ กล่องข้อความจะไหลเลื่อนตกลงมาซ้อนกัน และหน้าจอด้านล่างแตกกระจายเป็นโพลิกอนสามเหลี่ยม 3D ทั่วจอ
* **สาเหตุที่แท้จริงที่ค้นพบจากการ Reverse Engineering**:
  1. สคริปต์เวอร์ชันก่อนหน้าเข้าใจผิดว่าพื้นที่ข้อความจบที่ `0x0D758` (เนื่องจากเห็นพอยน์เตอร์ใน SLPS) จึงตัดจบและใส่ Padding `0x0000` ที่ Offset `0x0D758`
  2. แต่ในความเป็นจริง **Block ที่ 50 (Step 51) เริ่มต้นที่ `0x0D70C` และมีความยาว 94 ไบต์ ไปสิ้นสุดที่ `0x0D76A`**
  3. การตัดแบ่งที่ `0x0D758` จึงทำให้ **Block 50 ขาดครึ่งท่อน** และถูกแทนที่ด้วย `0x0000` จำนวนมาก
  4. เมื่อเอนจินรันบทสนทนามาถึงจุดนี้ ตัวเกมพยายามถอดรหัส `0x0000` เป็น Opcode ซึ่งชิป GPU ของ PS1 ตีความเป็นคำสั่งวาดโพลิกอน (GPU Primitives Command Packet) ทำให้เกิดอาการ **GPU Triangle Cascade** หน้าจอแตกกระจายและค้าง
* **การแก้ไขที่ถูกต้องและถาวร**:
  * **Section 2 มีขอบเขตที่แท้จริงคือ `0x0D634 .. 0x0D80E` (ขนาด 474 ไบต์ รวม 8 บล็อก)** และปิดท้ายด้วยคำสั่ง `<END>` (`0x3000`)
  * **Section 3 มีขอบเขตที่แท้จริงคือ `0x0D80E .. 0x0D956` (ขนาด 328 ไบต์ รวม 5 บล็อก)** และปิดท้ายด้วยคำสั่ง `<END>` (`0x3000`)
  * ทุกบล็อก (Block) จะมี Header Opcode ควบคุมมุมกล้อง/สไปรต์ตัวละคร เช่น `19 12 01 00 ... 04 00` ตามด้วยรหัสข้อความ และปิดท้ายบล็อกด้วย `0x2000` (หรือ `0x3000` ในบล็อกสุดท้ายของ Section)
  * **หากรักษา Header Opcode และคุมผลรวมความยาว Section ให้เท่ากับขนาดเดิมเป๊ะ (474 ไบต์ และ 328 ไบต์) บทสนทนาภาษาไทยจะแสดงผลได้อย่างราบรื่นและไม่มีการแครชหรือหน้าจอแตกอีกเลย 100%!**

### 3.2 กฎควบคุมการแปลบทสนทนาใน `R00.BIN`
1. **Section 0 (`0x0CCF4 .. 0x0D210`)**:
   * ความยาวรวมต้องเท่ากับ **1,308 ไบต์พอดีเป๊ะ** (27 บล็อก, Steps 1..27)
   * ต้องรักษา Opcodes ต้นบล็อกของแต่ละ Step ไว้ครบถ้วน
2. **Section 1 (`0x0D210 .. 0x0D634`)**:
   * ความยาวรวมต้องเท่ากับ **1,060 ไบต์พอดีเป๊ะ** (19 บล็อก, Steps 28..46)
   * บล็อกสุดท้าย (Step 46) ต้องจบที่ `0x0D632` ด้วย Terminator `0x2000`
3. **Section 2 (`0x0D634 .. 0x0D80E`)**:
   * ความยาวรวมต้องเท่ากับ **474 ไบต์พอดีเป๊ะ** (8 บล็อก, Steps 47..54: วาตารุ, โอบาบะ, ซาคุยะ)
   * บล็อกสุดท้าย (Step 54) ต้องปิดท้ายด้วย `0x3000` (`<END>`)
4. **Section 3 (`0x0D80E .. 0x0D956`)**:
   * ความยาวรวมต้องเท่ากับ **328 ไบต์พอดีเป๊ะ** (5 บล็อก, Steps 55..59: วาตารุ, ซาคุยะ เรื่องวาลมอนโด)
   * บล็อกสุดท้าย (Step 59) ต้องปิดท้ายด้วย `0x3000` (`<END>`)
5. **ระบบร้านค้า (Shopkeeper Relocation)**:
   * บทสนทนาร้านค้า `R00_098` .. `R00_101` มีขนาดยาวกว่าเดิมมาก ต้องใช้วิธีเขียนลงในพื้นที่ว่างท้ายไฟล์ (`0x116AC`, `0x1179C`, `0x11930`, `0x124E0`) แล้วอัปเดตตารางพอยน์เตอร์ RAM 32-bit ที่ `0x1233C`
6. **กฎข้อจำกัดของตาราง Token (`thai_table.json`)**:
   * ในการแปลบทสนทนา ห้ามใช้ตัวอักษรหรือพยางค์ที่ไม่มีอยู่ใน `thai_table.json` เช่น `รู้`, `นั่`, `ภู` มิฉะนั้นสคริปต์จะเกิด KeyError ให้ใช้คำที่แมปแล้ว เช่น `ที่`, `นั้`, `แดน`, `เป็น`, `โบราณ`, `ฝากตัวด้วยนะ` แทน

## 4. กฎเหล็กข้อที่ 3: กฎขนาดเซกเตอร์ CD-ROM และการจัดสรรพื้นที่

แผ่นเกม PS1 อ่านข้อมูลเป็นเซกเตอร์ (Sector ละ 2,048 ไบต์ของ User Data):
* **ไฟล์ `R00.BIN` บนแผ่นเกมมีโควตาความจุเท่ากับ 37 Sectors**:
  $$Target Size = 37 	imes 2,048 = 75,776 ไบต์$$
* **กฎเหล็ก**:
  * เมื่อฉีดข้อความและร้านค้าลงใน `R00.BIN` เรียบร้อยแล้ว หากขนาดไฟล์ยังไม่ถึง 75,776 ไบต์ จะต้องทำการเติม (Padding) ด้วยไบต์ `0x00` ให้มีขนาด **75,776 ไบต์ พอดีเป๊ะเสมอ**
  * ห้ามให้ขนาดไฟล์เกิน 75,776 ไบต์เด็ดขาด เพราะจะไปล้นทับเซกเตอร์ของไฟล์ถัดไปบนแผ่น CD

## 5. กฎเหล็กข้อที่ 4: การล็อกไฟล์บน Windows และขั้นตอนการทดสอบ Emulator

* **ปัญหา File Lock ของระบบปฏิบัติการ Windows**:
  * เมื่อโปรแกรมจำลอง **DuckStation** กำลังรันเกมอยู่ โปรแกรมจะถือสิทธิ์ล็อกไฟล์ `Wataru_Thai_Test.bin` หรือ `.cue` ไว้
  * หากรันสคริปต์ `repack_iso.py` ในขณะที่ DuckStation ยังเปิดอยู่ จะเกิดข้อผิดพลาด:
    `PermissionError: [Errno 13] Permission denied`
* **วิธีปฏิบัติที่ถูกต้อง**:
  1. ปิด DuckStation ก่อนทุกครั้งที่จะประกอบแผ่นใหม่
  2. หาก DuckStation ค้างอยู่ใน Process เบื้องหลัง ให้ใช้คำสั่ง:
     `taskkill /IM duckstation-qt-x64-ReleaseLTCG.exe`
  3. รัน `python 05_CD_ISO_TOOLS/repack_iso.py`
  4. เมื่อสร้าง CHD เสร็จสมบูรณ์ ค่อยเปิด DuckStation โหลดไฟล์ `Wataru_Thai_Test.chd` ขึ้นมาทดสอบ
